## 1. Режим пересчёта (ввод количества в графу)

Задача: вместо закрашивания ячеек — вводить количество прямо в графу «По факту».
Поиск/фильтры/заметки не менялись.

Финальная механика:
- Карандаш — цикл: выкл (серый, обычное листание) → подсветка (жёлтый) → пересчёт
  (зелёный, иконка белая) → выкл. Автовключения при загрузке НЕТ (убрано по требованию).
- Вход в ввод: тап по ячейке графы (автовход даже из обычного режима, кроме подсветки)
  или зелёный карандаш. Тап по строке: рамка на номенклатуре (фолбэк — первая колонка),
  тап по самой графе — рамка на ней.
- Цифры: первая заменяет содержимое ячейки, остальные дописывают; backspace/корзина —
  очистка текущей ячейки. Тап по полю поиска временно возвращает клавиатуру в поиск.
- В вводе панель поиска прячется (slim: значение + лупа возврата с фокусом).
- Заметка в пересчёте пишется в ячейку факта той же строки.
- Жёлтая рамка selection-ring во всех режимах (в подсветке — на lastTappedCell).
- Долгое удержание карандаша 850 мс = закрасить красным незакрашенные.

Детект колонок (`lib/utils.ts`, `detectCountColumns`): подсказки факт/кол-во/количество;
учет/учёт с ё→е нормализацией; отклонение; номенклатура. Порядок колонок НЕ меняется
(перестановку пробовали — убрали).

Отклонение = факт − учёт, считается сразу при вводе (`parseCountNumber` понимает запятую;
пустой факт = 0). Нет граф учёта/отклонения — только ввод.

Коммиты: `fee77e5` (режим), `33dd868` (без перестановки + дебаг), `51a1c46` (фикс
невидимого зелёного карандаша: в `index.css` добавлен `.bg-success!important` —
базовый `.bg-gray-800!important` душил bootstrap-овский), `28ca943`→`055cc56` (цикл
с/без выкл), `2b1bcb2` (без автовключения), `6850da1` (пароль деплоя в файл),
`705af04` (отклонение + формат).

## 2. Внешний вид скачанного XLSX

- Зачёркнутые ячейки: причина — исходный бланк 1С несёт шрифт Arial bold italic strike
  (доказано дампом шрифтов через ExcelJS; в приложении шрифты не рисуются, вылезло только
  после скачивания). Фикс `e777cbe`: снимать strike при экспорте.
- `d2312c9`: `normalizeCellLook` в App.tsx (шрифт 10.5, без italic/strike, тонкие рамки),
  зачистка шрифтов за пределами таблицы.
- `aa810d3`: убран bold везде, wrapText, автоподгон ширины колонок (только расширение).
- `0e72027`: автозаливка отклонения (минус — красное FFFF0000, плюс — зелёное FF00B050,
  ноль без заливки; ручная подсветка важнее автоцвета) + лист «С отклонениями» (строки
  с ненулевым отклонением целиком, подшапки групп, подсветки, заметки);
  `32f575d` переименовал лист в «Отклонения».
- Диагностика красного на основном листе (D/E/F красные, включая нули и плюсы, хотя код
  красит только F-ненулевые): вывод — это ручные подсветки highlightedCells, персистентные
  на сервере, автоцвет их не перекрывает; в приложении DataTable рисует их же (bg-red-800).
  Снимаются жёлтым карандашом + tap по красной ячейке.
- `b4e9361`: запас ширин, рамки пустым ячейкам на «Отклонениях» (явный цикл getCell —
  eachCell пропускает null), fit на листах красных/заметок. `9ebd5a0`: первая вкладка
  всегда «Основной лист».
- У юзера в браузере застревала старая сборка (SW cache-first): `9ba6799` поднял
  SW v2→v3 (`public/sw.js` CACHE_NAME) — форсит обновление оболочки.
- ФИНАЛ `af35c79`: по предложению юзера основной лист ВСЕГДА рисуем с нуля как
  «Отклонения», форматирование оригинала не нужно. Удалена вся overlay-ветка (~145 строк:
  load оригинала, spliceColumns/spliceRows, clear, copyFormatFromUchet, запись поверх,
  fallback-ветка). Остался единый свежий билд: шапка + normalize, строки через
  toExportRow, подсветки/заметки/автозаливка по ключам `${r}-${c}`, ширины inline.
  Экспорт пишет значения факта И отклонения числами (формулы отклонения оригинала
  становятся значениями), копирует alignment+numFmt с ячеек учёта.
